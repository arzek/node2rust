# Design

## Context

- Мотивація — див. `proposal.md`. Rust-коду в репозиторії ще немає: лише `CLAUDE.md`, `openspec/` і `.gitignore` (`.idea`, `runs`; файл закінчується без символу нового рядка).
- Toolchain на машині: активний `stable` — rustc і cargo 1.92.0; окремо встановлено 1.99.0.
- Формат уроку задає `CLAUDE.md` («Формат уроку»); вимоги до уроку 0 — у `specs/lessons/000-hello-world/spec.md`.
- Рішення перевірено прототипом поза репозиторієм на cargo 1.92.0. «Спостереження» нижче — результат запуску, «оцінка» — моє судження.

## Goals / Non-Goals

**Goals:**
- Урок 0 перевіряється одним `cargo test` з папки уроку, без мережі й залежностей.
- Наступний урок додається однією новою папкою, без правок у корені.
- Тести падають зі зрозумілою різницею «очікував / отримав».

**Non-Goals:**
- `PROGRESS.md` — рядок дописується під час закриття уроку (крок 4 у `CLAUDE.md`), не в цій зміні.
- Спільні залежності, лінти й профілі на рівні workspace — коли знадобляться конкретному уроку.
- Коміти — їх робить користувач.

## Decisions

### 1. Кореневий Cargo workspace, урок — окремий пакет

Кореневий `Cargo.toml` — virtual manifest: `[workspace]`, `resolver = "3"`, `members = ["lessons/*"]`.

- Чому: усі пакети workspace мають один `Cargo.lock` і один `target/` — спільний кеш збірки, коли з'являться tokio, axum і sqlx; новий урок підхоплюється сам ([workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html)). Оцінка: IDE бачить усі уроки як один Cargo-проєкт з кореня.
- Спостереження: `cargo test` з папки уроку виконує лише цей пакет; `Cargo.lock` і `target/` з'являються в корені. Без `resolver` cargo попереджає `virtual workspace defaulting to resolver = "1"`, тому він заданий явно.
- Альтернативи: (а) кожен урок — самостійний пакет: свої `target/` і `Cargo.lock` у кожній папці, залежності збираються заново для кожного уроку; (б) явний список `members`: зайва папка нічого не ламає, але кожен урок потребує правки кореневого маніфесту.

### 2. Правило: кожна папка в `lessons/` — Cargo-пакет

- Спостереження: папка без `Cargo.toml` у `lessons/` ламає завантаження всього workspace (`failed to load manifest for workspace member`); файл `.DS_Store` — ні.
- Тому папка уроку й її маніфест створюються разом. Запасний вихід — `workspace.exclude`.

### 3. Назва пакета — `lesson-000-hello-world`

- Спостереження: назву пакета, що починається з цифри, cargo відхиляє (`the name cannot start with a digit`), тож папка `000-hello-world` не може дати назву пакету.
- Схема `lesson-NNN-<тема>` унікальна в межах workspace і працює в `cargo test -p …` з кореня. Бінарник дістає ту саму назву.
- Маніфест уроку — рівно те, що генерує `cargo new` (спостереження): `name`, `version = "0.1.0"`, `edition = "2024"`, порожній `[dependencies]`.

### 4. Стартовий код — порожній `main`

- `src/main.rs`: `fn main` з одним TODO-коментарем англійською. Компілюється без попереджень, нічого не друкує.
- Спостереження: `cargo new` сам генерує програму з привітанням. Тому стартовий код її не містить, а приклад у README друкує інший текст — рядок учень пише сам.

### 5. Тести — інтеграційний тест, що запускає бінарник

- `tests/hello_world.rs`, лише `std`: `std::process::Command` запускає зібраний бінарник за шляхом із `env!("CARGO_BIN_EXE_lesson-000-hello-world")`. Cargo сам збирає бінарник перед інтеграційним тестом і задає цю змінну; назва береться як є, з дефісами ([environment variables](https://doc.rust-lang.org/cargo/reference/environment-variables.html), [integration tests](https://doc.rust-lang.org/cargo/reference/cargo-targets.html#integration-tests)).
- Два тести: `prints_hello_world_to_stdout` (stdout дорівнює `Hello, world!\n`) і `exits_successfully_and_keeps_stderr_empty`. Порівняння через `assert_eq!`, щоб у звіті були `left` і `right`. Файл починається з коментаря «do not edit».
- Спостереження: на стартовому коді `cargo test` повертає 101 і падає лише перший тест (`left: ""`, `right: "Hello, world!\n"`); на еталонному розв'язку — `2 passed`; інший регістр, вивід без `\n`, вивід у stderr і ненульовий код завершення дають червоний результат.
- Другий тест зелений уже на старті — свідомо: він ловить «правильний stdout, але падіння або шум у stderr».
- Спостереження: `ExitStatus` сам друкується як `exit status: 1`, тож повідомлення в `assert!` не має повторювати цей префікс.
- Альтернативи: крейт `assert_cmd` — зовнішня залежність і мережа вже в уроці 0; функція `greeting()` у `lib.rs` з unit-тестом — тягне бібліотечний крейт, типи повернення й `&str` раніше за їхні уроки.

### 6. README — план змісту

- Теорія (3–5 речень): Cargo — менеджер пакетів, збірка й тест-ранер в одному; `Cargo.toml` і `src/main.rs` з `fn main`; `println!` — макрос (знак `!`), рядок формату перевіряється під час компіляції; `cargo run` збирає нативний бінарник у `target/debug/` — рантайм на кшталт `node` не потрібен; `cargo test` і папка `tests/`.
- Приклад: `fn main` із `println!` та іншим текстом.
- Порівняння (таблиця, 5–7 рядків): `Cargo.toml` ↔ `package.json`; `Cargo.lock` ↔ `package-lock.json`; `cargo run` ↔ `nest start`; `cargo test` ↔ `jest`; `fn main()` у `src/main.rs` ↔ `bootstrap()` у `src/main.ts`; `println!` ↔ `console.log`; `target/` ↔ `dist/`.
- Завдання: надрукувати рівно `Hello, world!`, змінюючи лише `src/main.rs`.
- Команда для перевірки: `cargo test` з папки уроку; поруч — `cargo run`, щоб побачити вивід.
- Ліміт у 40 рядків жорсткий, перевіряється через `wc -l`.

### 7. Еталонний розв'язок — лише поза репозиторієм

- Зелений стан і хибні варіанти перевіряються в тимчасовій копії папки уроку в scratchpad. Спостереження: копія поза workspace працює як самостійний пакет зі своїм `target/`.
- Код розв'язку не потрапляє ні в папку уроку, ні в артефакти зміни: їх читає сам учень.

### 8. `.gitignore`: `target/` ігнорується, `Cargo.lock` — ні

- `cargo new` за замовчуванням теж відстежує `Cargo.lock` у git ([FAQ](https://doc.rust-lang.org/cargo/faq.html#why-have-cargolock-in-version-control)).
- Спостереження: `git check-ignore target/` (зі слешем) спрацьовує ще до появи каталогу.

## Risks / Trade-offs

- [Папка без `Cargo.toml` у `lessons/` ламає всі уроки] → правило з рішення 2; помилка cargo називає винну папку; запасний вихід — `workspace.exclude`.
- [Зламаний маніфест одного уроку блокує cargo в усіх уроках] → в уроці 0 учень маніфест не редагує; повертаємось до цього, коли уроки почнуть додавати залежності.
- [Артефакти зміни читає сам учень — це спойлери] → в артефактах лише умова й опис тестів, без коду розв'язку.
- [README не вміщується в 40 рядків] → таблиця порівняння скорочується до 5 рядків.
- [Завдання тривіальне: таке саме привітання генерує `cargo new`] → свідомо: мета уроку 0 — цикл уроку й інструменти, а не код.
- [Термінал та IDE можуть використовувати різні toolchain (1.92.0 і 1.99.0) зі спільним `target/`] → лише зайві перезбирання, результат той самий (оцінка).
